# Outpost: project notes

Read this first in a new Claude Code session. It describes what the app is, where everything lives, and how it is tested. **Keep it up to date: every change to the app should update the relevant section and add a line to the Change log at the bottom.**

## What it is

Outpost is an offline "pocket kit" web app for iPhone (and Android), installed from Safari with Share → Add to Home Screen. Live at **https://fr5quency.github.io/outpost** (GitHub Pages, `main` branch, repo root). No build step, no server: static files only.

- Owner's online name in testing: whatever is set in the app (stored on the phone).
- English and Arabic (switch at the top of every screen); dark mode by default, light mode switch.
- Everything works offline after the first load, except online multiplayer.

## App structure (index.html)

- Tabs: Home, Stack (Kiwix / Organic Maps / PocketPal AI checklists with App Store + Google Play links), Tools (encoder, hash, AES vault, units, password, coordinates, SOS beacon), Notes, Field (first-aid etc. cards, numbers, go-bag), Games. In Arabic mode only: القرآن and الأذكار tabs.
- Helpers: `$`, `$$`, `tr()` (translate via `AR`; missing keys are collected in `window.__miss`), `store.get/set` (localStorage with `outpost.` prefix), `modal()`, `toast()`, `show(view)`, global state `S`.
- Every new user-visible English string needs an entry in the `AR` dictionary (search `"Games":"الألعاب",` to find a good insertion point).
- Click handling is one delegated listener using `data-act` attributes.

### Chess (the biggest part)
- Engine: `ChessEngine(scope)` (0x88 board, alpha-beta, quiescence). Passes the standard perft suite and Chess960 perft positions. Runs in a Web Worker built from `ChessEngine.toString()`. Variants: `setVariant(0 std / 1 king of the hill / 2 three-check)`, Chess960 via FEN castling letters.
- Modes: 9 bots (400–2000 Elo, `LEVELS`), modes Standard/Chess960/King of the Hill/Three-check/No castling (bots and 1v1 only), 1v1 pass-and-play (board flips each move), online (PeerJS), puzzles.
- Game state: `CH` (`mode`: bot / mp / hot / puz).
- Review engine: **Stockfish 18** (`SF`, `sfQueue`, `sfJob`) for Standard and No-castling games: per position `go depth 20 movetime 1000` with MultiPV 2 (best move, score, second-best score for "only move"), plus a 500 ms search of the played move if it was not one of the top two. Mate scores are mapped onto the built-in engine's scale (±100000). Newest position first; jobs of a closed game are dropped. Chess960 / King of the Hill / Three-check use the built-in engine (`anLocal`), and so does everything if Stockfish cannot load (`sfFail`, state −1). Rows made by Stockfish carry `sf:1`. Checked against Morphy's Opera Game: 13.Rxd7 and 16.Qb8+ Brilliant, 15…Nxd7 Blunder, White 99% accuracy.
- Engine shown: every analysis row has `sf` (1 Stockfish, 0 built-in; `null` = saved before this was recorded). `engineName(rows)` → "Analysed by Stockfish 18 / Built-in engine / both" in the review summary; saved games keep `eng` (sf / local / mix), shown in the history row.
- Board size: `sizeBoard` ignores `#coachBox`, `#revLine` and `#mlist`, so the review text never shrinks the board; the coach text is capped at 4 lines and scrolls.
- Game review: moves are analysed in the background during play (`queueAn`, `onAnalysis`), classified by `classifyPly` (brilliant/great/best/excellent/good/book/inaccuracy/mistake/miss/blunder), summary modal, coach text (`COACH`) spoken with the phone's speech synthesis. Live brilliant: ding + !! badge until the next move.
- Ratings: online Elo (starts 800, standard formula, rating exchanged at match start; abandoned game = loss next launch) and offline Elo (starts 400; beat higher bot → take its rating, lose to lower bot → −10, beat lower/equal → +5). Separate, stored as `eloOnline` / `eloOffline`.
- Game history (`chessGames`, newest first, max 100): `archRecord` saves every finished bot / online / 1v1 game from `finishChess` (not puzzles): moves, colour, result + reason, opponent name + Elo, your Elo before/after, date, start FEN for Chess960. Analysis rows are packed (`packRow`) and stored with the game (`archRows`, also called as analysis arrives after the game ends and when a review finishes), with the accuracy. Screen `S.game="chessHist"` (`renderChessHist`: W/D/L totals, All/Online/Bots/1v1 filter). `openArch(id)` rebuilds `CH` with `CH.arch` set (no clocks, no rating, Elo shown as it was); "Game review" works as usual. A tappable move list (`#mlist`, `moveList()`) appears under the board once a game is over; it is not counted in the board size. Synced with the account like everything else.
- Arrows: double-tap a square to start, double-tap another to finish; single tap clears.
- Board look: green chess.com-style colours, coordinates small in the corners (`.cr`/`.cf`), pieces 90% of a square, no CSS filters on pieces (iPhone renders filtered elements blurry).

### Online play
- PeerJS public broker + WebRTC. Matchmaking: whoever claims the lobby ID (`outpost-pocketkit-chess-lobby-v1`, plus `-four` / `-blocks`) waits; others connect to it. Games register handlers in `MPG` (chess in index.html; `window.OUTPOST_MP.register` for Four in a Row in games-more.js; block battle in index.html).
- Online: chess (15 min each), Four in a Row (30 s per move), Block Puzzle score battle (3 min, same pieces from a shared seed).
- Never tested against the real PeerJS servers (blocked from the build sandbox); tested with a BroadcastChannel stand-in.

### Account & sync (sign in)
- Top bar button `#acctBtn` (between the OUTPOST brand and the ONLINE pill) opens a full-screen page `#acctPage` with "‹ Back", **Continue with Google** and **Continue with Apple** (disabled, "Coming soon" until an Apple Developer account exists). Signed in: avatar, name, email, last-synced time, Sync now, Log out.
- Firebase project `outpost-f3a72` (config `FB_CFG` in index.html; it is public by design). Google sign-in uses `signInWithPopup`, falling back to `signInWithRedirect`. Authorized domain needed: `fr5quency.github.io`.
- Database: **Cloud Firestore**, called through its REST API with the user's ID token (no Firestore SDK, to keep the app small). One document per user: `users/{uid}` with `data` (JSON string of every `outpost.*` localStorage key) and `updatedAt`.
- Security rules (published in the Firebase console): `match /users/{uid} { allow read, write: if request.auth != null && request.auth.uid == uid; }`
- If sync shows `(download 403)` / `(upload 403)`: the Firestore rules are missing or not published (Firestore Database → Rules → paste → Publish). This happened once at setup; publishing the rules fixed it.
- Never uploaded (per-phone meta keys): `probe`, `eloPending`, `acct`, `syncAt`, `syncDirtyAt`, `syncUid`.
- How sync works: `store.set` calls `window.__syncHook`, which stamps `syncDirtyAt` and uploads 4 s later. On open / coming online / returning to the app, the newer copy wins (`updatedAt` in the cloud vs `syncAt` / `syncDirtyAt` on the phone); pulling cloud data replaces local keys and reloads the page.
- First sign-in on a phone (`syncUid` differs): cloud empty → upload; phone has no real data (only lang/theme/name-type settings) → restore silently; both have data → ask "Use my account's data" / "Keep this phone's data".
- Log out uploads pending changes first and keeps the data on the phone.
- Every sync step has a 20 s limit (`timeout`, `fsFetch`), and `syncNow` always clears "Syncing…" in a `finally`. If sync fails, the account screen shows the reason in brackets (e.g. `download 403`, `timeout`, `signed-out`). Toasts sit above the account page (`body.acctopen`).
- `sw.js` ignores requests to other sites (Google sign-in, Firestore, PeerJS) so they always go to the network.
- Real Google sign-in was not testable from the build sandbox; sync was tested with a fake Firestore + fake auth (first upload, auto-upload, fresh-phone restore, conflict choice, older phone pulls newer data, logout keeps data).

## Testing

Tests are Playwright scripts run against `python3 -m http.server 8765` in the repo folder (Chromium is pre-installed in Claude Code cloud sessions). They lived in the session scratchpad and are not committed; recreate as needed. What was checked each time:
- Chess engine perft (standard + Chess960), bot-vs-bot strength, puzzles (all 100 solved through `puzMove`), modes, review, online (two pages + fake PeerJS), Elo rules.
- Every game in games-more.js (rules + UI), Quran (604 pages = 6236 ayat), Arabic `__miss` list empty, no JS errors, no horizontal overflow at iPhone width.

## Release checklist

1. Make the change; add Arabic strings to `AR`.
2. Bump `CACHE` in `sw.js` (add any new file to its list).
3. Test in a phone-sized browser; check `window.__miss` is empty and there are no page errors.
4. Commit and push to `main`; GitHub Pages updates in ~1 minute.
5. Update this file (sections above + change log below).
6. On the phone: open Outpost on Wi-Fi, close it fully, open it again.

## Known limits / ideas

- iPhone Safari cannot vibrate web pages; haptics use a switch-toggle trick that only works on recent iOS.
- Before a sync on app start, `syncNow` waits up to 8 s for Firebase to restore the saved sign-in.
- Online Elo is stored on each phone and in the user's own account document, so it is not tamper-proof.
- Sign in with Apple needs an Apple Developer account ($99/yr): Services ID + key, then enable Apple in Firebase Authentication.
- Optional hardening: restrict the Firebase API key to `fr5quency.github.io` in Google Cloud Console → Credentials.
- App Store: would need a Mac, Apple Developer account ($99/yr) and a wrapper such as Capacitor (see conversation notes).
